Вариант 2. Список книг для чтения.
Назначение: хранить книги, искать их, отмечать прочитанные и считать статистику страниц.
Проверено на Python 3.12.10. Интернет и внешние библиотеки не нужны.

Файлы:
main.py — консольное меню, ввод и сообщения.
logic.py — проверка записей и действия с книгами.
storage.py — чтение и сохранение JSON.
test_logic.py — проверки логики без меню.
test_storage.py — проверки файлов во временной папке.
data.json — небольшой вымышленный пример.

Запуск из папки lab12:
python main.py

Запуск тестов:
python test_logic.py
python test_storage.py

При запуске из другой папки data.json всё равно берётся рядом с main.py.
После распаковки абсолютные пути в коде менять не нужно.

Меню:
1 — показать все книги по возрастанию ID.
2 — добавить книгу с начальным статусом «не прочитана».
3 — найти книги по непустой части названия без учёта регистра.
4 — явно установить статус: 1 — прочитана, 0 — не прочитана.
5 — удалить книгу по ID только после ответа да.
6 — показать статистику текущего списка.
7 — сохранить данные.
8 — выйти с вопросом о сохранении.

Формат data.json:
Список словарей с обязательными полями id, title, category, amount, completed.
id — положительное целое число, уникальное внутри списка.
title и category — непустые строки; при добавлении пробелы по краям удаляются.
amount — целое количество страниц не меньше нуля, bool вместо числа запрещён.
completed — строго bool: True означает, что книга прочитана.
Дополнительные поля допускаются и сохраняются при записи.
В JSON логические значения записываются как true и false.

ID новой книги равен максимальному существующему ID плюс один.
Для пустого списка первый ID равен 1. После удаления остальные ID не меняются.
Одинаковые названия разрешены, потому что записи различаются по ID.

Всего 4 книги, прочитано 2, не прочитано 2.
Сумма страниц: 96 + 180 + 400 + 120 = 796.
По категориям: Справочная 120, Учебная 400, Художественная 276.

Как сохраняются данные:
Сначала проверяется весь набор и создаётся строка JSON.
Затем она записывается в data.json.tmp рядом с основным файлом.
Только после успешной записи временный файл заменяет data.json.
Поэтому ошибка записи не стирает прежний основной файл.
